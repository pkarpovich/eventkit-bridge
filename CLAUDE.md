# eventkit-bridge

A Rust daemon inside `EventKitBridge.app` that serves an HTTP API over the Mac's calendars and reminders by running two bundled, pinned CLIs: `ekctl` (v1.8.0) for calendars and `remindctl` (v0.3.8) for reminders. With an optional `[mail]` table it also reads Apple Mail's local store (`~/Library/Mail/V<n>`) directly, read-only, and makes one mail write, junk or not junk, through Mail.app over Apple Events (`osascript`). The bridge enforces one thing, the read/write policy over calendars and reminder lists, and the visibility rules over mail accounts and mailboxes. With an optional `[auth]` table, `src/auth/` (`mod.rs` validation and the scope table, `jwks.rs` the JWKS cache, `fetch.rs` the HTTP fetch) also requires an OAuth 2.0 bearer token, an RS256 JWT access token validated locally against the provider's JWKS, with one scope per route. See `README.md` for the API, and `docs/plans/completed/2026-10-05-eventkit-bridge.md`, `docs/plans/completed/2026-10-05-reminders.md`, `docs/plans/completed/2026-10-05-mail.md` and `docs/plans/completed/2026-10-06-mail-junk.md` and `docs/plans/completed/2026-10-07-bearer-auth.md` for the design.

## Gate

`mise run check` must pass: `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`. Where `mise` is unavailable, run the three cargo commands directly. `shellcheck scripts/*.sh` must be clean.

## Code conventions

- Apply the `rust-style` skill to every Rust file.
- `#![forbid(unsafe_code)]` at the crate root (`src/lib.rs`, `src/main.rs`). No unsafe, so no `libc`; use safe wrappers such as `rustix`.
- The library (`src/lib.rs`) holds every module; `src/main.rs` is only the CLI and daemon wiring. A new module is declared in `lib.rs` the moment it is created, or its tests never compile.
- The crate builds and tests on Linux as well as macOS. Nothing links an Apple framework; macOS is reached only through the `ekctl`, `remindctl`, `osascript` and `launchctl` subprocesses and by reading Mail's files, and no test runs any of them for real, talks to Mail or reads a real `~/Library/Mail`. Mail tests build a fixture store with `src/mail/fixture.rs` from `fixtures/mail_schema.sql`. Tests use the fake script in `src/fake_ekctl.rs` (for both CLIs and `osascript`) and a recording fake for launchctl. Auth tests mint tokens with a key pair generated at test time, serve the JWKS from a scripted `JwksSource`, and test `HttpJwksSource` against a local `TcpListener`; no test reaches a real provider.
- No test may run the real `ekctl` or `remindctl`: from a terminal, TCC would attribute the calendar or reminders access to the terminal app.
- Lint findings are fixed in code. No `#[allow(...)]` except a narrow one on a single item with its reason stated in the PR. No blanket `#[allow(dead_code)]`; an item that exists only for tests is `#[cfg(test)]`.
- Tests live inline in a `#[cfg(test)] mod tests` block in the file they cover, and cover success and error paths.
- No comments. `///` doc comments on `pub` items only.
- No function with 4 or more parameters: pass a struct.
- Every subprocess call has a deadline and is killed when it expires (`kill_on_drop(true)`). Every runner (`src/ekctl.rs`, `src/remindctl.rs`, `src/mail/script.rs`) spawns through `src/subprocess.rs`, which owns the deadline, the stdout cap, the stderr tail and `CallOutcome`; never copy that into a runner.
- HTTP tests drive the real `axum::Router` with `tower::ServiceExt::oneshot`; no sockets.

## Rules that protect the security model

- **Only `src/ekctl.rs` builds `ekctl` argv.** Every option is `--name=value`, every event id goes after a literal `--`, and `ekctl` is run directly, never through a shell. No route ever passes client input to `ekctl` except through these typed builders.
- **Only `src/remindctl.rs` builds `remindctl` argv**, under the same rules: `--name=value` options, ids after a literal `--`, `--json --no-input` on every command, no shell.
- **Only `src/mail/script.rs` builds `osascript` argv.** The program is `/usr/bin/osascript`, run directly, never through a shell. The AppleScript is a compile-time constant with an `on run argv` handler; account uuid, mailbox paths, message id and the junk value are separate argv entries after the script and are never interpolated into script text. Mail writes are serialized by their own mutex, not `StoreLock`, and have a 30 s deadline.
- **Reminder and list ids must be full UUIDs** before they reach `remindctl` argv. `remindctl` reads an id argument as an "index or ID prefix", so a short number would address a row from its last listing. Anything else is `400`.
- Every `ekctl` and `remindctl` call goes through one shared lock (`StoreLock` in `src/subprocess.rs`), because both write to the same EventKit store. A write holds one session across its policy check (`show event` or `info`) and the write itself.
- Reminder writes go only to `write_lists`. `POST` names its list, and `PATCH` and `DELETE` run `info` first and refuse unless the reminder is in a write list.
- Writes go only to `write_calendars`. `POST` names its calendar, and `PATCH` and `DELETE` run `show event` first and refuse unless the event is in a write calendar. They also refuse a recurring event with `409`: `ekctl` resolves an id to the series' first occurrence and saves with `.thisEvent`, so the change would land on the wrong occurrence. Keep that refusal until `ekctl` can address one occurrence.
- The bridge never listens on an unspecified address.
- **Only `src/auth/` parses and validates tokens.** RS256 only, a `kid` required, `typ` `at+jwt`; `iss`, `aud` (present and containing `audience`) and the client are checked by the bridge's own code, not by library defaults. The raw token and the claims never leave the module; `AuthError` carries only a kind. A refusal body never names the failing check.
- **The bearer check is a second gate, not a replacement.** `require_bearer` runs after the `Host` check and before the body limit. `/healthz` stays token-free, exempted inside the middleware next to the scope table.
- **Every route in `router()` other than `/healthz` has a row in the scope table** in `src/auth/mod.rs`, and a test in `src/server.rs` walks `routes()` to enforce it. A new route gets its scope in the same change. `HEAD` uses the `GET` row.
- **Tokens are never logged**, nor the `Authorization` header, nor any claim beyond the client id, nor the `WWW-Authenticate` value. The request line carries only `client=<id>` or `client=anonymous`; a refusal logs only its kind. The JWKS body is never logged; a failed fetch logs its status or error kind. A test in `src/server.rs` asserts this; keep it passing.
- Every request's `Host` (and absolute-form authority) must be the listen IP or a configured `hosts` name; the check runs before any route, so DNS rebinding from a tailnet browser cannot reach a handler.
- **Never logged:** event titles, notes, locations, urls or attendees, and reminder titles or notes, from requests or from `ekctl`/`remindctl` output. The only exception is the startup listing (calendar id, title and source; reminder list id and title; place names and radii), which the user needs to fill in the config. A test in `src/server.rs` asserts this; keep it passing when adding routes or log lines.
- **Mail SQL is parameterised.** No query string is ever built from request input; filters are bound as named parameters, and id sets as one `rarray` parameter.
- **The Envelope Index is opened read-only and never `immutable`.** `SQLITE_OPEN_READ_ONLY`, `PRAGMA query_only = 1` and a busy timeout, one connection per request on `spawn_blocking`, outside `StoreLock`. Mail writes the WAL concurrently, and `immutable=1` would hide it. The bridge never writes Mail's files.
- **Message paths are confined to the mail root.** A `.emlx` path is built from the mailbox URL and the `ROWID` partition rule, canonicalised, and refused unless it stays under the canonical root. An error returned to a client names only the kind of failure, never the path.
- **Mail visibility:** only accounts in `[mail.accounts]`, never an excluded mailbox, never a `deleted = 1` row. An invisible message is `404`, the same as an unknown id.
- **The single mail write is junk / not junk, performed by Mail.app over Apple Events.** `PATCH /v1/mail/messages/{id}` moves a visible message to its account's junk mailbox or inbox and nothing else: no sending, deleting, flagging, marking read or other moves. An error body never carries `osascript` stderr, only the kind of failure.
- **Never logged from mail:** addresses, display names, subjects, summaries, bodies or attachment names. Request lines carry only a row count, and for a junk request the account name and the junk value; never a Message-ID, a mailbox path or `osascript` stderr beyond its error code. The only exception is the startup account listing (account uuid, kind, `Accounts4.sqlite` type and description, counts, newest date). A test in `src/server.rs` asserts this; keep it passing.
- **Place addresses and coordinates are never logged or returned**, not in the startup listing, `--check-config`, `/v1/places`, a reminder's `location` or a `remindctl` error (a failed geocode names the address, so `Session::add` replaces it with the place name). A location trigger is reported only by its config place name and proximity. Types holding an address (`config::Address`, `RcLocationTrigger`) implement `Debug` by hand to print `<redacted>`; never derive it.

## Bundle id

The bundle id `dev.pkarpovich.eventkit-bridge` (and the signing identifiers `dev.pkarpovich.eventkit-bridge.ekctl` and `dev.pkarpovich.eventkit-bridge.remindctl`, the LaunchAgent label and `AssociatedBundleIdentifiers`) must never change. TCC keys the Calendars, Reminders, Full Disk Access and Automation (Mail) grants to it, so changing it silently revokes every user's permission and makes them approve the prompt again (or re-add the app under Full Disk Access).

## Release

- `ekctl` is pinned in `scripts/fetch-ekctl.sh` and `remindctl` in `scripts/fetch-remindctl.sh` (version, URL, sha256). `fixtures/*.json` (`fixtures/remindctl_*.json` for `remindctl`) matches the output of that version, with personal values replaced, and the tests treat it as the tool's output contract. A bump updates the script, re-captures the fixtures from the app bundle (never from a terminal), and updates the version here and in the README.
- `fixtures/mail_schema.sql` is the subset of Mail's Envelope Index (data version `V10`) that the bridge reads, and `SCHEMA` in `src/mail/store.rs` lists the same tables and columns for the `mail schema changed` health check. When a macOS release changes the format, update both together with the README note in "Turning on mail". Capture the schema from a copy of the index, never with message data.
- The Homebrew cask is written inline by `.github/workflows/release.yml`. Its `caveats` repeat the README "First run" steps, including `100.64.0.1:8790`, and the optional Full Disk Access and Automation steps from "Turning on mail"; change both together.
