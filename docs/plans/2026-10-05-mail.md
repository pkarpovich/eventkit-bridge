# Mail in eventkit-bridge

## Overview

eventkit-bridge 0.4.0 adds read-only access to the mail Apple Mail has already downloaded on the Mac, next to calendars and reminders. Every account configured in Mail is covered: iCloud, Gmail, Outlook, Exchange and plain IMAP. The bridge never talks to a mail server and needs no account credentials.

It reads two things Mail keeps on disk:
- the **Envelope Index**, a SQLite database with one row per message (sender, recipients, subject, summary, dates, mailbox, flags);
- the **`.emlx` files**, which hold the full message.

The database is opened read-only, and nothing under `~/Library/Mail` is ever written.

```
HTTP client (on the tailnet) --HTTP--> eventkit-bridge (EventKitBridge.app, Full Disk Access) --read-only--> ~/Library/Mail/V10
```

This plan builds on 0.3.0 (reminders) and starts after it is merged.

## Skills to invoke

- `rust-style` - every Rust file.

## Non-goals

- Sending, moving, flagging, marking read or deleting mail.
- Attachment contents. Names, types and sizes are listed, bytes are not served.
- Full-text search over message bodies. Search covers sender, recipients, subject and Mail's stored summary.
- Talking to Mail.app (AppleScript) or to any mail server.

## Rejected alternatives

- **AppleScript or JXA against Mail.app.** Slow on tens of thousands of messages, needs Mail running, and breaks on UI-level changes.
- **IMAP, EWS or Graph from a server.** It needs a login per account and OAuth app registrations for Gmail and Microsoft, while Mail on the Mac already has every account synced.
- **A separate daemon only for mail.** It would keep Full Disk Access away from the process that writes calendars and reminders, at the cost of a second app, cask and LaunchAgent to maintain. One bridge was chosen; the README states plainly that enabling mail means granting Full Disk Access to EventKitBridge.

## Context (verified on macOS 27.0, Mail data version V10)

- **Store layout:** `~/Library/Mail/V10/MailData/Envelope Index` (SQLite, written by Mail in WAL mode) and `~/Library/Mail/V10/<account uuid>/<mailbox path>.mbox/<store uuid>/Data/.../Messages/<id>.emlx`.
- **Tables used:**
  - `messages(ROWID, sender, subject, summary, date_sent, date_received, mailbox, read, flagged, deleted, size, conversation_id, ...)`. `sender`, `subject` and `summary` are foreign keys into `addresses`, `subjects` and `summaries`; dates are Unix seconds.
  - `subjects(ROWID, subject)`.
  - `addresses(ROWID, address, comment)`. `comment` is the display name.
  - `summaries(ROWID, summary)`.
  - `recipients(message, address, type, position)`. `type` 0 = To, 1 = Cc, 2 = Bcc, to be confirmed against a real store in Post-Completion.
  - `mailboxes(ROWID, url, total_count, unread_count)`. `url` is `<scheme>://<account uuid>/<url-encoded mailbox path>`; schemes are `ews`, `imap` and `local`.
  - `message_global_data(message_id, message_id_header)`. The `Message-ID` header, used to collapse a message that Gmail shows in two mailboxes (Inbox and All Mail).
- **File names.**
  - The `.emlx` file name is the message `ROWID`.
  - The directory under `Data/` is the decimal digits of `ROWID / 1000`, in reverse order, one directory per digit: `383621` -> `Data/3/8/3/Messages/383621.emlx`, and below 1000 directly `Data/Messages/<id>.emlx`. The rule held for every file in a store of tens of thousands of messages.
  - Some messages exist only as `<id>.partial.emlx` (headers and part of the body), and a small share of rows has no file at all.
  - Files without a row are leftovers of deleted messages and are never read.
- **`.emlx` format:** the first line is the byte length of the RFC 822 message that follows, then the message, then an XML plist with Mail's flags.
- **Accounts.** The account uuid in a mailbox URL is the `ZIDENTIFIER` of a row in `~/Library/Accounts/Accounts4.sqlite` with type `com.apple.account.Exchange` or `com.apple.account.IMAP`. IMAP accounts often have an empty description there, so the names clients see come from the bridge config.
- **TCC.** `~/Library/Mail` is protected by Full Disk Access. There is no prompt: the user adds EventKitBridge in System Settings > Privacy & Security > Full Disk Access. The grant is keyed to the signed bundle at its fixed path, like the Calendars and Reminders grants. No entitlement is needed.
- **Crates** (add with `cargo add`): `rusqlite` with the bundled SQLite, `mail-parser`, `html2text`.

## Solution Overview

### Config

A new optional `[mail]` table. Without it, mail is off and no mail code runs.

```toml
[mail]
exclude_mailboxes = ["Trash", "Deleted Items", "Junk", "Junk Email", "Spam", "[Gmail]/Trash", "[Gmail]/Spam"]
# root = "/path/to/Mail"   optional, for development and tests

[mail.accounts]
"<account uuid>" = "main"
"<account uuid>" = "gmail"
```

- **`[mail.accounts]`** maps an account uuid to the name clients see; names match `^[a-z0-9][a-z0-9-]{0,39}$`. **Accounts not listed are invisible.**
- **`exclude_mailboxes`** lists decoded mailbox paths, compared case-insensitively. The default is the list above.
- **`root`** (optional) defaults to the highest `~/Library/Mail/V<n>` that contains `MailData/Envelope Index`.
- **Startup listing.** When `[mail]` is present, the daemon logs one line per account uuid found in the mailboxes table: uuid, type and description from `Accounts4.sqlite` when readable, mailbox count, message count, the date of the newest message, and whether it is configured. This is how the user fills `[mail.accounts]`. Addresses and subjects are not logged.
- **`--check-config`** prints the account names and excluded mailboxes, and never opens the store.

### Store access

- **Opening the database.** A connection opens `Envelope Index` with `SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_NO_MUTEX`, a 2 s busy timeout, and `PRAGMA query_only = 1`. One connection per request, run on `spawn_blocking`. Mail reads do not take the EventKit runner lock.
- **Never `immutable=1`.** Mail writes the WAL concurrently, and the reader must see it.
- **Message paths.** A message's path comes from its mailbox URL (account uuid plus decoded path, each segment suffixed `.mbox`) and the `ROWID` partition rule.
  - The store-uuid directory is found by listing the `.mbox` directory.
  - The bridge tries `<id>.emlx`, then `<id>.partial.emlx`.
  - A canonicalised path must stay under `root`; anything else is refused.
- **Parsing** uses `mail-parser` on the bytes after the length line.
  - The body is the first `text/plain` part, otherwise the first `text/html` part converted with `html2text`.
  - The body is capped at 100 000 characters, with `body_truncated: true` when cut.
  - Attachments are listed as `{name, content_type, size}`.

### HTTP API

The same rules as the other routes: the `Host` allowlist (`421`) and `{"error": ...}` bodies. Mail routes are `GET` only.

**Shared types:**

```json
Account: {"name":"main","type":"exchange","mailboxes":[{"path":"Inbox","total":812,"unread":3}]}
MessageSummary: {"id":383621,"account":"main","mailbox":"Inbox","date":"2026-10-05T15:35:13+02:00",
                 "from":{"name":"...","address":"..."},"to":[{"name":"...","address":"..."}],
                 "subject":"...","summary":"...","read":false,"flagged":false,"has_body":true}
Message: MessageSummary + {"cc":[...],"body":"...","body_truncated":false,"partial":false,
                           "attachments":[{"name":"report.pdf","content_type":"application/pdf","size":120334}]}
```

- Dates are RFC 3339 in the Mac's local zone.
- `type` is `exchange`, `imap` or `local`.
- `has_body` is false when no `.emlx` exists; `GET /v1/mail/messages/{id}` then returns `body: null`.
- `partial` is true when only `.partial.emlx` exists.

**Routes** (all `404` when `[mail]` is absent):

- **`GET /v1/mail/accounts`** -> `{"accounts":[Account]}`. Configured accounts only, excluded mailboxes left out.
- **`GET /v1/mail/messages`** -> `{"messages":[MessageSummary],"next_cursor":...}`, newest first by `date_received`.
  - Query parameters:
    - `account` (repeatable; a configured name);
    - `mailbox` (a path within those accounts);
    - `from`, `to` (RFC 3339 bounds on `date_received`);
    - `q` (case-insensitive substring over subject, sender name and address, recipient addresses and summary);
    - `unread=true`;
    - `limit` (1-100, default 25);
    - `cursor` (opaque, from the previous page).
  - Rows where `deleted = 1`, in excluded mailboxes, or in unconfigured accounts never appear.
  - A message with the same `Message-ID` in several mailboxes of one account appears once, under the first mailbox that is not Gmail's `All Mail`.
  - An unknown account name or mailbox is `400`.
- **`GET /v1/mail/messages/{id}`** -> `Message`. `404` when the id is not a visible message: deleted, excluded, unconfigured account or unknown id all look the same.

### Health

- When `[mail]` is present, `/healthz` also opens the store, verifies the tables and columns above, and checks that every configured account uuid has mailboxes. The result is cached with the rest of the check.
- New degraded reasons:
  - `mail no access` - the database cannot be opened, which is how a missing Full Disk Access grant shows up;
  - `mail schema changed` - a table or column is missing;
  - `mail account missing` - a configured account uuid has no mailboxes.
- The `200` body gains `"mail_accounts": <n>` and `"newest_message_age_s"`, so a monitor can notice when Mail stopped syncing.

### Logging

Per request: method, route template, status, duration and row count. **Never logged:** addresses, names, subjects, summaries, bodies or attachment names.
