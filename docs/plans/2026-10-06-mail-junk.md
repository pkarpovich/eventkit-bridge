# Mark mail as junk or not junk

## Overview

eventkit-bridge 0.6.0 lets a client move a message into its account's junk mailbox, or back to the inbox, through Mail.app. A client that reads mail through the bridge can then clean up spam that reached the inbox and rescue a message that Mail or the server filed as junk.

Reading stays as it is: the Envelope Index is opened read-only and the bridge never writes to Mail's files. The write goes through Mail.app over Apple Events, so Mail performs the move and syncs it to the server like a click in Mail would, and Gmail and Exchange train their filters on it.

```
client --PATCH /v1/mail/messages/{id} {"junk": true}--> eventkit-bridge --osascript (Apple Events)--> Mail.app --> server
```

This is the only mail write. Sending, replying, deleting, flagging, marking read and moving to any other mailbox stay out of scope.

## Skills to invoke

- `rust-style` - every Rust file.

## Non-goals

- Moving a message to an arbitrary mailbox, archiving, deleting, flagging, marking read or unread.
- Writing to the Envelope Index or to `.emlx` files. Mail.app does every change.
- A config switch for the write. Mail is already opt-in (`[mail]`), only accounts in `[mail.accounts]` are visible, and macOS asks the user once before EventKitBridge may control Mail.
- Batch requests. One message per request; a client loops.

## Context (verified on macOS 27.0 with Mail data version V10, against Exchange, Gmail IMAP and iCloud IMAP accounts)

- **Ids match.** The AppleScript `id` of a Mail message is the Envelope Index `messages.ROWID`, the id the bridge already serves. The AppleScript `id` of an account is the account uuid in the mailbox URL, the key of `[mail.accounts]`.
- **Addressing.** `first message of mailbox "<path>" of account id "<uuid>" whose id is <id>` finds a message in about 0.2 s. `<path>` is the full mailbox path from the Envelope Index URL, decoded, exact case: a nested Gmail mailbox works as `mailbox "[Gmail]/Spam"`. Case matters: Gmail's inbox is `INBOX`, Exchange's is `Inbox`, and the wrong case is error `-1728`.
- **Junk status does not move.** `set junk mail status of m to false` on a message in the junk mailbox leaves it there. Moving takes an explicit `move m to mailbox "<path>" of account id "<uuid>"`, which returns at once.
- **A moved message gets a new id.** Mail gives the moved copy a new `ROWID`; the old id stops resolving. The copy keeps its RFC 822 `Message-ID`, so `messages of mailbox "<target>" of account id "<uuid>" whose message id is "<Message-ID>"` finds it. In the test it was visible both to AppleScript and to the bridge's Envelope Index reads within 2 s.
- **Junk mailbox names** seen across providers: `[Gmail]/Spam` (Gmail), `Junk Email` (Exchange), `Junk` (iCloud and most IMAP), `Spam` (some IMAP). The inbox is `INBOX` or `Inbox`.
- **TCC.** The first Apple Event from EventKitBridge to Mail shows the system prompt "EventKitBridge wants to control Mail". Denied, every later call fails with error `-1743` until the user enables it in System Settings > Privacy & Security > Automation. A hardened-runtime app needs the `com.apple.security.automation.apple-events` entitlement for the prompt to appear at all, and `NSAppleEventsUsageDescription` in its `Info.plist` for the prompt text. The prompt and the grant are attributed to EventKitBridge even though `/usr/bin/osascript` sends the events, because the bridge is the responsible process.
- **Mail must be running.** An Apple Event to Mail launches it when it is not.

## Design

### Route

`PATCH /v1/mail/messages/{id}` with the body `{"junk": true}` or `{"junk": false}`. `junk` is required, the only field, and a boolean; anything else is `400` under the existing body rules (unknown fields, wrong types, empty body).

The message must be visible under the existing mail rules (configured account, not an excluded mailbox, not deleted); otherwise `404 message not found`, the same as `GET`. With no `[mail]` table the route answers the same `404 mail is off` as every other mail route.

Target mailbox, picked from the mailboxes of the message's account in the Envelope Index:
- `junk: true`: the first mailbox whose path matches, case-insensitively, `[Gmail]/Spam`, `Junk Email`, `Junk E-mail`, `Junk`, `Spam`, in that order. None is `409 account has no junk mailbox`.
- `junk: false`: the mailbox whose path matches `INBOX` case-insensitively. None is `409 account has no inbox`.

The stored path, exact case, is what goes to Mail.

Then, in one `osascript` call: find the message in its current mailbox, read its `Message-ID`, set `junk mail status` to the requested value, and move it to the target unless it is already there. Setting the status as well as moving is what makes the providers train their filters.

`200` answers:

```json
{"id": 383622, "account": "work", "mailbox": "Inbox", "junk": false}
```

- `id` is the message's id after the move: the new id when it moved, the same id when it was already in the target. It is `null` when the moved copy did not show up in the target within 5 s, or when the target mailbox is excluded by `mail.exclude_mailboxes` (it then exists but is not visible through the bridge).
- `account` is the configured account name, `mailbox` the target path, `junk` the requested value.

### The Mail runner

A new module, `src/mail/script.rs`, is the only place that builds `osascript` argv. Rules, the same as for `ekctl` and `remindctl`:
- The program is `/usr/bin/osascript`, run directly, never through a shell.
- The AppleScript is a compile-time constant with an `on run argv` handler. Account uuid, source path, message id, target path and the junk value are passed as separate argv entries after the script and are never interpolated into the script text.
- It spawns through `src/subprocess.rs` with a 30 s deadline and `kill_on_drop(true)`.
- Mail writes are serialized by their own `tokio::sync::Mutex`, not by `StoreLock`: they do not touch the EventKit store, and one slow Mail call must not hold up calendar and reminder requests.

The script, in outline:

```applescript
on run argv
  set {acctId, sourcePath, msgId, targetPath, junkValue} to argv
  tell application "Mail"
    set acct to account id acctId
    set m to first message of mailbox sourcePath of acct whose id is (msgId as integer)
    set rfcId to message id of m
    set junk mail status of m to (junkValue is "true")
    if sourcePath is targetPath then return msgId
    move m to mailbox targetPath of acct
    repeat 25 times
      set hits to (messages of mailbox targetPath of acct whose message id is rfcId)
      if (count of hits) > 0 then return (id of item 1 of hits) as text
      delay 0.2
    end repeat
    return ""
  end tell
end run
```

Output is the new id or an empty line; anything else is a runner error.

### Errors

`osascript` exits non-zero with `execution error: ... (<code>)` on stderr. Map by code:
- `-1743`: `503 Mail automation not permitted: allow EventKitBridge to control Mail in System Settings > Privacy & Security > Automation`.
- `-1728`: `404 message not found` (the message moved or was deleted between the Envelope Index read and the Apple Event).
- `-1712` (timeout) or the deadline: `504 Mail did not answer`.
- Anything else: `502 Mail failed`.

The response never carries the stderr text: it can contain a mailbox path, and the README promises error bodies name only the kind of failure.

### Logging

The request line logs the route template, status, duration, account name and the junk value. Never logged: subjects, addresses, Message-IDs, mailbox paths other than the configured account name, and the `osascript` stderr beyond its error code.

### Security model changes

- The README "Security model" and CLAUDE.md lose "Mail ... read-only" and gain: mail is read from the Envelope Index read-only; the single write is junk / not junk, performed by Mail.app over Apple Events; the bridge never writes Mail's files.
- New CLAUDE.md rule: **only `src/mail/script.rs` builds `osascript` argv**, with a constant script and argv-passed values.
- `entitlements.plist` gains `com.apple.security.automation.apple-events`; `Info.plist.template` gains `NSAppleEventsUsageDescription` ("EventKitBridge asks Mail to move a message to junk or back to the inbox when a client requests it.").
- The README "Turning on mail" section gains a step: the first junk request shows the Automation prompt; allow it.

## Development Approach

- **Testing approach:** Regular (code first, then tests in the same task).
- Complete each task fully before the next; small, focused changes.
- **Every task includes new or updated tests** for the code it changes, covering success and error paths.
- **All tests must pass before the next task starts.**
- No test runs the real `osascript` or talks to Mail. Tests use a fake `osascript` script in the style of `src/fake_ekctl.rs`, driven by the runner's configurable program path.
- Update this plan when scope changes.
